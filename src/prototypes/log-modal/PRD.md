## 一、需求背景

### 1.1 业务背景（可选）

国际物流B2B业务中，订单从创建到完成需要经过创建、审核、配载、出库等多个环节，每个环节的操作需要留痕以便溯源。运营、财务、客服等人员在日常工作中，经常需要查看某个订单的操作历史来了解变更过程、追溯责任人或定位问题。当前各系统间操作日志分散，缺少统一展示入口。

### 1.2 现状问题（必选）

- **操作日志查看入口分散**：运营人员若要了解订单变化过程，需要登录不同系统分别查看，效率低且容易遗漏关键信息
- **责任追溯困难**：当出现订单数据异常时，无法快速定位到具体操作人和操作系统，排查周期长
- **操作来源不清晰**：无法区分操作是来自客户系统（CCOS）、订单管理（OMS）、运单处理（OFP）还是核心系统（NUC），影响问题定位效率
- **操作人身份区分缺失**：内部操作人（员工）和外部操作人（客户）混在一起，无法区分责任归属

### 1.3 需求目的（必选）

- 提供一个**统一的弹框入口**，集中展示订单全生命周期的操作日志
- 每条日志清晰记录**操作来源系统、操作人、操作内容、操作时间**四个要素
- 支持**内部操作人**和**外部操作人**区分展示，内部操作人需展示工号和姓名，外部操作人展示客户代码，便于责任追溯
- 操作日志按时间顺序由新到旧排列，支持垂直滚动查看完整历史记录

## 六、功能清单

### 功能明细

| 序号 | 系统 | 菜单/模块 | 最终效果 |
|------|------|----------|---------|
| 01 | B2B订单系统 | 订单详情 - 日志记录 | 点击"日志"按钮，弹框展示该订单全生命周期操作日志，按操作时间由新到旧排列 |
| 02 | B2B订单系统 | 日志记录弹框 | 弹框标题"日志记录"，无底部按钮，仅右上角X关闭 |

### 功能整体交互

- **触发条件**：用户进入订单详情页后，点击"日志"按钮，弹框打开
- **弹框关闭**：点击右上角X按钮，弹框关闭
- **日志加载**：弹框打开时自动加载该订单对应的全部操作日志数据
- **内容显示**：日志以表格形式展示，固定高度，超过可见区域的内容自动垂直滚动
- **搜索/分页**：不提供搜索筛选功能，不提供分页功能

## 七、功能描述

### 7.1 弹框布局

弹框打开后直接展示日志列表，无搜索筛选区。

| 属性 | 说明 |
|------|------|
| 弹框标题 | 日志记录，标题前显示蓝色竖线装饰符 |
| 弹框宽度 | 960px |
| 底部按钮 | 无，仅右上角X关闭按钮 |
| 表格显示区域 | 固定显示10行的高度，超出10行的内容自动垂直滚动查看 |

### 7.2 展示列定义

| 列名 | 业务含义 | 展示规则 |
|------|---------|---------|
| 序号 | 日志编号，从1开始递增，按操作时间由新到旧排列 | 数字显示，最靠近当前时间的操作为序号1 |
| 操作系统 | 标识该条操作记录来源于哪个业务系统 | 仅限以下4个枚举值之一：CCOS（客户系统）、OMS（订单管理系统）、OFP（运单处理系统）、NUC（核心系统） |
| 内部操作人 | 公司内部员工操作人，用于精确追溯到具体执行员工 | 格式固定为"工号(姓名)"，如"zt27979(卓运康)"；若该操作无内部操作人则此列留空 |
| 外部操作人 | 外部客户操作人，用于识别该操作由哪个客户发起 | 展示客户代码，如"BN0001"；若该操作无外部操作人则此列留空 |
| 操作内容 | 具体执行的操作内容，描述该条日志记录的关键信息 | 文本展示，超过列宽的内容以省略号截断，鼠标悬停可查看完整内容 |
| 操作时间 | 该条操作发生的具体时刻 | 格式为"yyyy-MM-dd HH:mm:ss"，精确到秒 |

**列宽度说明**（仅作参考，最终以UI设计为准）：
- 序号列宽度较小，仅容纳数字
- 操作系统列宽度容纳4个字符
- 内部操作人列宽度容纳工号+姓名的完整格式
- 外部操作人列宽度容纳客户代码
- 操作内容列自适应占满剩余宽度
- 操作时间列固定宽度容纳19个字符的时间戳

### 7.3 业务规则

**规则一：操作系统枚举**

| 系统代码 | 说明 |
|---------|------|
| CCOS | 客户系统，客户操作入口，由外部操作人发起 |
| OMS | 订单管理系统，运营人员在后台进行订单管理操作 |
| OFP | 运单处理系统，配载、出库等仓库环节操作 |
| NUC | 核心系统，系统自动触发的操作（如状态变更、定时任务） |

**规则二：操作人显示规则**

每条日志记录最多可展示一个内部操作人和一个外部操作人，两个字段独立。

- **内部操作人**：仅在公司内部员工操作时填写，格式为"工号(姓名)"，例如"zt27979(卓运康)"
- **外部操作人**：在客户或外部系统操作时填写，展示客户代码，例如"BN0001"
- **特殊情况**：
  - 系统自动操作（NUC系统）：内部操作人显示系统标识，如"sys_system(系统)"；外部操作人显示"SYSTEM"
  - 只有内部操作的记录：外部操作人列留空
  - 只有外部操作的记录：内部操作人列留空

**规则三：排序规则**

- 所有日志记录按操作时间由新到旧降序排列
- 时间精确到秒，同一秒内的多条记录按自然顺序排列

**规则四：数据显示规则**

- **正常情况**：弹框打开后，表格展示该订单的全部操作日志
- **数据为空**：若该订单无任何操作日志，表格展示空状态提示"暂无操作记录"
- **数据较少**：不足10行时，表格高度自适应收缩
- **数据超出10行**：表格固定高度，超出的行自动垂直滚动
- **水平滚动**：所有列内容均在弹框宽度内完整显示，不出现水平滚动条

**规则五：内容截断规则**

- 操作内容文本长度超过列宽时，显示省略号(...)截断
- 用户将鼠标悬停在截断的内容上时，通过浮层展示完整内容

### 7.4 弹框打开与关闭逻辑

| 操作 | 触发条件 | 结果 |
|------|---------|------|
| 打开弹框 | 用户点击"日志"按钮 | 弹框打开，日志数据即刻加载并展示 |
| 关闭弹框 | 用户点击右上角X按钮 | 弹框关闭 |

## 八、验证标准

|------|---------|---------|---------|

| 2 | 弹框关闭 | 用户点击右上角X按钮 | 弹框关闭，返回订单详情页 |
| 3 | 数据正常展示 | 订单有15条操作日志 | 表格展示15条记录，按操作时间由新到旧排列 |
| 4 | 操作系统列 | 查看操作系统列内容 | 正确显示CCOS/OMS/OFP/NUC四种系统代码之一 |
| 5 | 内部操作人格式 | 查看内部操作人列 | 显示"工号(姓名)"格式，如"zt27979(卓运康)" |
| 6 | 外部操作人格式 | 查看外部操作人列 | 显示客户代码，如"BN0001" |
| 7 | 表格高度 | 数据量超过10行 | 固定显示10行高度，超出行自动垂直滚动 |
| 8 | 数据量不足10行 | 订单只有3条日志 | 表格高度自适应，不出现空白区域 |
| 9 | 数据为空 | 订单无任何操作日志 | 表格显示"暂无操作记录"空状态提示 |
| 10 | 内容超长截断 | 操作内容文本过长 | 超出列宽时显示省略号，鼠标悬停浮层显示完整内容 |
| 11 | 系统自动操作展示 | 操作系统为NUC的记录 | 内部操作人显示系统标识，外部操作人显示SYSTEM |
| 12 | 内部/外部操作人留空 | 仅内部操作或仅外部操作的记录 | 对应列留空，不显示任何占位符或默认值 |
| 13 | 水平滚动 | 检查弹框是否有水平滚动 | 无水平滚动条，所有列内容均在弹框宽度内 |
| 14 | 多语言 | 切换语言环境 | 弹框标题、列名、空状态提示等界面文案均切换为对应语言 |
| 15 | 浏览器兼容 | 在不同浏览器打开 | 兼容Windows谷歌、火狐；Mac谷歌、火狐、Safari |

### 2. 造数需求

| 数据类别 | 数据要求 | 验证场景 |
|---------|---------|---------|
| 完整数据集（15条） | 涵盖4种操作系统（CCOS/OMS/OFP/NUC）、至少3种不同的操作人、多种不同类型的操作内容 | 验证正常展示、排序、滚动 |
| 空数据集 | 该订单无任何日志记录 | 验证空状态提示 |
| 少量数据（3条） | 仅3条日志，不足10行 | 验证表格自适应高度 |
| 超长内容数据 | 1条操作内容特别长（超过50个字符） | 验证内容截断和悬停浮层 |
| 操作人留空数据 | 1条内部操作人留空、1条外部操作人留空 | 验证空列展示 |
| 系统自动操作数据 | 操作系统为NUC | 验证系统标识展示 |

### 3. 风险点说明

| 风险类型 | 风险描述 | 应对措施 |
|---------|---------|---------|
| 业务风险 | 日志数据量过大时（如超过100条），固定高度滚动影响用户定位效率 | 当前为原型阶段，固定展示10行满足验证需求；后续迭代可根据实际数据量增加搜索筛选或分页功能 |
| 数据风险 | 操作内容字段可能包含敏感信息（如客户手机号、地址等），前端展示存在泄露风险 | 操作内容需由后端做脱敏处理后下发，前端仅展示，不做额外处理 |
| 展示风险 | 内部操作人工号+姓名的格式可能在不同系统间不一致，部分记录可能缺少姓名 | 工号+姓名的拼接在后端完成，前端不自行拼接，保证格式统一 |

## 九、非功能需求

### 1. 多语言

- **是否支持多语言（必选）**：是，默认中英文
- 需要翻译的内容：弹框标题"日志记录"、表格列名（序号/操作系统/内部操作人/外部操作人/操作内容/操作时间）、空状态提示"暂无操作记录"
- 不需要翻译的内容：操作系统枚举值（CCOS/OMS/OFP/NUC）、操作人、操作内容、操作时间

### 2. 多时区

- **是否支持多时区（必选）**：是，需要支持多时区
- 操作时间展示时根据当前用户所在的时区自动转换
- 后端下发的操作时间应为统一标准时间（如UTC），前端根据用户时区做转换

### 3. 安全合规

- 操作日志涉及操作人信息（工号、姓名、客户代码），相关信息仅限内部系统使用
- 操作内容字段不得包含客户敏感信息（如密码、支付信息等），需由后端过滤
- 内部操作人工号和姓名的展示仅在内部系统可见

### 4. 权限

- 日志记录弹框作为订单详情的附属功能，不单独设置权限
- 用户在订单详情页的权限决定其是否能查看日志

### 5. 性能

| 性能维度 | 要求 |
|---------|------|
| 弹框打开速度 | 从点击"日志"到弹框内容完全展示，不超过1秒 |
| 大量数据场景 | 1000条日志数据加载到表格展示，不超过2秒 |
| 并发场景 | 支持至少50个用户同时打开订单日志 |

### 6. 浏览器兼容性

- **浏览器兼容**：兼容Windows的谷歌、火狐；苹果电脑Mac系统的谷歌、火狐、Safari
- **自适应兼容**：分辨率自适应1440~1920；小于1440时固定为1440宽度，出现横向滚动条
